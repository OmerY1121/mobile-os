# Mobile OS v0.0.6

Mobile OS v0.0.6

This release adds PID namespace isolation and improves how system services are started, stopped and recovered after failures.

Changes

* Added a dedicated PID namespace for statusd, with a small supervisor running as PID 1 inside the namespace.
* Kept the existing mount isolation, restricted /proc access and separate service credentials.
* Updated the service manager to clean up remaining child processes when a service exits.
* Added SIGTERM handling with SIGKILL as a fallback for processes that refuse to stop.
* Changed restart handling so a normal exit doesn’t count as a failure.
* Added ping, uptime and stop commands to statusctl. The stop command requires root authorization.
* Added automated QEMU tests for booting, restarting services and handling shutdowns.

Testing

* Existing IPC tests passed after the changes.
* Confirmed that statusd runs as PID 2 inside its own namespace, with the supervisor running as PID 1.
* Tested three consecutive service failures and confirmed that the restart limit was enforced.
* Tested cleanup using a service that exits while leaving another process running. The remaining process ignored SIGTERM, allowing us to check the SIGKILL fallback.
* Verified that a service exiting with code 0 is not restarted.
* Added tests for the new IPC commands and their authorization behavior.
* Added make test-all to run the existing system tests together.

Fixes

* Corrected the handling of normal service exits so they no longer trigger unnecessary restarts.
* Improved cleanup of processes left behind after a service crashes.
* Extended the tests to cover failure conditions rather than only successful startup.

Limitations

* The service manager still handles only statusd.
* Process isolation is not a complete application sandbox.
* The system still runs as a Linux-based prototype without a graphical interface.
* Root-only shutdown testing requires a test environment with the necessary privileges.

Next

Add ARM support and begin testing the system on a different architecture.
