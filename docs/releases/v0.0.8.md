# Mobile OS v0.0.8

## Changes

- Added `logd` and `logctl` for local logging, log rotation and access-controlled IPC.
- Added boot event logging and the `logctl boot` command.
- Reworked `init` to manage multiple services independently.
- Added `services.conf` to configure enabled services and restart limits.
- Added service state reporting, including failure counts and last exit status.
- Added `statusctl services` and `statusctl health`.

## Testing

- Passed x86-64 QEMU boot, IPC and service recovery tests.
- Verified service configuration and access permissions.
- Verified health checks against missing, working and unresponsive logging services.
- Tested service state reporting and recovery after killing `logd` inside QEMU.
- Passed ARMv7 QEMU boot and regression tests.
- Passed offline Galaxy S3 boot image checks.

## Fixes

- Added recovery for a stale `logd` socket after a crash.
- Fixed service state updates when the last exit status changes.
- Added connection timeout handling and meaningful health command exit codes.

## Limitations

- The Galaxy S3 image has not been boot-tested on physical hardware and is not ready for flashing.
- Passing offline image checks does not guarantee that the phone will boot.
- Display, touchscreen, mobile networking and other phone hardware are not yet implemented or verified.
- Service health checks cover the current IPC and logging services, not the health of the entire system.
- This remains an experimental development system, not a usable phone operating system.

## Next

- Continue hardware bring-up and service infrastructure work.
- Extend diagnostics and system management as additional components are introduced.
